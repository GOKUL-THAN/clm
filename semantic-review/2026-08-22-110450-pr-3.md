# Secure leased gateway command transport (v3)

This change replaces anonymous/destructive gateway polling with per-satellite credentials, production mTLS, PostgreSQL command leases, and a durable gateway-side result journal. Credentials are generated once, stored as scrypt hashes, bound to the route satellite and tenant, and can be rotated or revoked through tenant-authorized APIs. Delivery now separates claim, acknowledgement, lease renewal, execution, result reporting, dead-letter handling, cancellation, and explicit operator retry. The security and state-machine design is coherent, but the source packaging is not reproducible from version control.

**Watch for:** **confirmed** — `.gitignore` excludes the gateway `internal/state`, `internal/secrets`, and deployer `internal/.../data` source packages, including the new command journal and tests; **confirmed** — PostgreSQL state-machine tests compiled but skipped without `CLM_TEST_DB_DSN`, and no live mTLS/CA/provider path was exercised.

**Verdict**: NEEDS_CHANGES

## High-level view

Registration and rotation return a random bearer value once while persisting only a salted scrypt hash. Gateway routes bind that credential to the route satellite and server-derived tenant; production also requires a CA-verified client certificate with a matching URI/DNS SAN, while anonymous v1 behavior survives only behind an explicit non-production switch.

Commands are tenant-scoped and idempotent, with atomic `FOR UPDATE SKIP LOCKED` claims, expiring lease tokens, acknowledgement/renewal guards, bounded backoff, dead-lettering, cancellation, and authorized re-execution. Automatic lease reclamation changes the delivery attempt but preserves the execution generation; only operator retry increments it, allowing the gateway to distinguish redelivery from deliberate re-execution.

The gateway acknowledges before execution, renews long leases, refuses unknown types, applies execution timeouts, bounds the complete serialized result envelope, and persists outcomes before reporting them. Duplicate suppression uses command ID plus execution generation, and confirmed upstream results are removed from the journal.

The implementation is currently all-untracked, and broad runtime-artifact ignores also match required Go package directories. Consequently, a normal commit omits source needed by clean builds; separately, the strongest database and PKI behaviors remain compile/unit evidence rather than executed integration evidence in this review environment.

Production config requires server TLS, a gateway client CA, `client_auth=required`, safe transport bounds, and disabled legacy auth. The shared listener verifies presented client certificates, and route middleware requires one only on gateway routes so browser/JWT APIs can share the port; the connector independently rejects production HTTP and insecure verification while loading its server CA, client keypair, and server name.

## Lease and duplicate-suppression evidence stops at the database boundary

The non-obvious safety choice is the split between delivery attempts and execution generations. Lease expiry can issue a new token without authorizing repeated side effects, while explicit tenant-authorized retry resets delivery state and increments the generation. The gateway persists a generation-scoped outcome before posting it, replays that outcome on redelivery, fails closed on journal corruption, and deletes it only after the control plane confirms the result.

**Confirmed validation gap:** focused unit tests cover credential hashing, route/SAN binding, production fail-closed config, authentication concurrency, serialized result limits, journal restart/corruption/concurrency, and execution-generation suppression. PostgreSQL cases cover idempotent replay/conflict, claim exclusivity, token and expiry guards, result replay, retry, dead-lettering, and operator retry generation, but `TestMain` skipped them because `CLM_TEST_DB_DSN` was unset. The local machine also lacks `go`, so this review could recheck shell syntax and byte-identical migration copies but could not independently repeat the staged Go commands; the implementation run reports test, vet, and build success for all three components.

**Not tested:** live client/server certificate negotiation and SAN failure, live credential rotation/revocation, PostgreSQL repository behavior in this final pass, cloud-provider bootstrap, or adapter reconciliation after an indeterminate external side effect.
